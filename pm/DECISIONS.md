# DECISIONS

## D-001 · 2026-11-07 · Working name "Tell"
**Decision:** Repo and product are called Tell (as in a poker tell). Unverified for trademark/domain/handles; alternates offered in the kickoff message.
**Why:** Short, sayable, literally the thing the product finds. Easy to rename later (grep `Tell`).

## D-002 · 2026-11-07 · Platform for the hackathon: web app on a laptop
**Decision:** v1 is a local FastAPI + single HTML page. No phone integration this weekend.
**Why:** iOS exposes no third-party access to cellular call audio; Android default-dialer is too heavy for <24 h; the judging criteria are provable privacy and a convincing demo, both achievable on a laptop.

## D-003 · 2026-11-07 · Passive, local listen-and-judge. No talk-back.
**Decision:** Doublespeak listens and judges; it never answers or speaks to the caller. Liveness challenges are out of scope (team decision 14:12).
**Why:** Team wants the product to be invisible to the caller. Differentiation is local + open + ensemble + provable, not an active protocol.

## D-004 · 2026-11-07 · Core architectural rule: models interpret, code decides; caller audio never leaves the device
**Decision:** `scorer.py` is deterministic; the LLM (off by default) only adds Tells. The analysis path has no network imports (enforced by `tests/test_privacy.py`); `privacy.record_egress` rejects audio by construction; every verdict is HMAC-signed and bound to the clip hash.
**Why:** The track is judged on "what leaves the device, who can read it, can you prove it" — so the privacy claim is a test and a meter, not a sentence in a deck.

## D-005 · 2026-11-07 · Four-tier verdict (Human · AI disclosed · AI undisclosed · Scam) + "unsure"
**Decision:** AI ≠ scam. Disclosure short-circuits to `ai_disclosed`; scam intent overrides everything; low confidence shows "unsure" with the same advice.
**Why:** Legit AI callers are required to identify themselves under TCPA, so non-disclosure is itself a meaningful signal; and a false "safe" on a family-emergency call is the worst outcome, so we never say "safe".

## D-006 · 2026-11-07 · Gradium: attacker simulator + spoken verdict only
**Decision:** Gradium TTS generates red-team clips (incl. a cloned teammate) and speaks the verdict. Caller audio never goes to Gradium STT in v1; transcripts are pasted or produced locally.
**Why:** Keeps the privacy guarantee intact while using Gradium meaningfully for the Best Use of Gradium side prize (which stacks with Privacy-First): red-team clips from our own cloned voices + the optional spoken verdict, with only our own script text ever sent to Gradium.

## D-007 · 2026-11-07 · Data to collect from day 1 (post-hackathon, opt-in only)
**Decision:** Per verdict: tier, p_ai, p_scam, confidence, which tells fired, clip duration, band-limited flag, user correction (thumbs up/down). Never audio, never transcript, unless the user explicitly donates a clip to the eval set.
**Why:** Enough to tune thresholds and measure false positives on real people without holding anyone's calls.

## D-008 · 2026-11-07 · Neural ensemble on-device
**Decision:** Add local neural voters beside the behavioral tells: an open anti-spoof checkpoint (HF or ONNX), local Whisper (faster-whisper) for the transcript, and a local 3B model via Ollama for scam-talk. All are voters; `scorer.py` still decides.
**Why:** Hardcoded acoustic heuristics are a floor. Neural voters catch vocoder artifacts (incl. live voice conversion) that behavioral tells miss. Caller audio still never leaves the device: Whisper and the anti-spoof model run in-process, Ollama runs on localhost.

## D-009 · 2026-11-07 · Caller audio may reach 127.0.0.1 only, through `doublespeak/localhost.py`
**Decision:** Local engines that run as separate processes on the same machine (VoiceStudio STT on 127.0.0.1:3900, Ollama on 127.0.0.1:11434) may receive caller audio or transcript over loopback. All such traffic goes through one module, `doublespeak/localhost.py`, which hard-codes host `127.0.0.1`/`::1`, refuses any other host, and counts requests as `localhost_requests` in the egress meter (never as external egress). `doublespeak/llm.py` and `doublespeak/speak.py` remain the only other modules allowed to open a socket, and only with text. Caller audio still cannot reach any non-loopback host; `caller_audio_bytes_sent` stays 0.
**Why:** Whisper in-process is the fallback, but VoiceStudio (646-language STT) and Ollama are the local engines the team chose; they are separate apps. Narrows D-004's "no network imports on the analysis path" to: none except loopback via that one module.
**Consequences:** `tests/test_privacy.py` allowlist becomes exactly {localhost.py, llm.py, speak.py}, plus a test that `localhost.py` rejects non-loopback hosts; web counter keeps `caller_audio_bytes_sent` (external) and adds `localhost_requests`. The third-party app is trusted not to phone home: verify once with Wi-Fi off. VoiceStudio is AGPL-3.0: use over HTTP only, never copy its code. Written from the team lead's instruction; review before merging `feat/local-plumbing`.


## D-010 · 2026-11-07 · Final name: Doublespeak (code, package, env vars, repo)
**Decision:** The product is **Doublespeak** everywhere. Python package `services/api/tell` → `services/api/doublespeak`; env vars `TELL_*` → `DOUBLESPEAK_*`; verdict signature prefix `tell1:` → `ds1:`; GitHub repo `aaravjain151/tell` → `aaravjain151/doublespeak`. Supersedes D-001's working name "Tell". (Sanath's brand-only rename commit `bdda80f` called itself D-009; D-009 is the loopback-audio decision, this is its proper record.)
**Kept on purpose:** a *tell* is still the word for one detection cue (pauses too regular, urgency phrase). The `Tell` record type, the `tells` field in the API and "tells" in the UI stay, because they name signals, not the product. Tagline "Every voice has a tell." still works.
**Why:** The name echoes Orwell's 1984 (doublespeak: words that say the opposite of what they mean), which is exactly what a cloned or scripted caller does, and fits the hackathon theme.
**Consequences:** Teammates must re-clone or `git fetch && git reset` to the renamed repo; old env files need `TELL_SIGNING_KEY` → `DOUBLESPEAK_SIGNING_KEY`; old signatures (`tell1:`) no longer verify, so inline demo samples are regenerated.

## D-011 · 2026-11-07 · Live call analysis over one loopback WebSocket, RAM-only ring buffer (PROPOSED)
**Status:** PROPOSED. Written by a developer agent from the issue #26 brief; needs a human to accept, amend or reject. Nothing else depends on it yet.
**Decision:** The app analyses a call while it happens through `WS /ws/stream` on the local API. Audio sources (browser tab, BlackHole capture, a native tap, `tools/stream_wav.py`) are pluggable and send 16 kHz mono PCM16. Each session keeps audio only in a RAM ring buffer (30 s default, 120 s cap); every 3 s of new audio one job runs the existing `pipeline.analyze` on the last 10 s in a worker thread and pushes the raw verdict. Auth is `POST /session` (allowed UI Origin) returning a single-use 60 s 256-bit token that the first WebSocket message redeems; max 2 sessions, 2 h per session, 15 s heartbeat. Stop, kill, heartbeat timeout, disconnect, `DELETE /session/{id}` and `POST /panic` zero the ring. `side=mix` caps displayed confidence at 0.6.
**Why:** Detecting a scam after the call ends is too late; D-003 (passive) and D-004/D-009 (audio never leaves the device, loopback only) rule out cloud streaming and any speaking to the caller. A ring plus per-hop re-analysis reuses the deterministic pipeline unchanged ("models interpret, code decides"). A browser WebSocket cannot set headers and a token in a URL leaks into logs and history, hence the hello message.
**Assumptions (unverified):** (1) re-running the full pipeline on a 10 s window every 3 s fits the CPU budget on the demo Mac; the first tick on a cold server lagged 11 s in a replay at 2x. (2) Per-tick raw verdicts are noisy on short windows; a stabiliser (another branch) will own what is displayed and alerts. (3) Any local process can call `/session` by sending an allowed Origin, so the token and Origin check stop web pages and DNS rebinding, not local malware. (4) The 0.6 mix cap is a judgement, not a measured number. (5) One shared worker thread is acceptable for two sessions. (6) No real microphone, BlackHole or native source was tested.
**Consequences:** `pipeline.analyze` gains `ephemeral=True` (ignores `DOUBLESPEAK_DEBUG_SAVE`, skips the history file); `limits.py` gains `handshake_allowed`. New files `ring.py`, `session.py`, `stream.py` import no network, subprocess or dynamic-import module, so `test_import_scan.py`'s ALLOWLIST is unchanged; `test_stream.py` adds no-disk-write and DEBUG_SAVE-ignored checks. Caller-audio copies inside an in-flight analysis outlive a wipe until it returns (bounded by the analyze timeout). `scorer.py` and `thresholds.py` are untouched.

## D-012 · 2026-11-07 · Companion capture: phone microphone audio to the user's OWN computer over a USB cable only (PROPOSED)
**Status:** PROPOSED. Written by a developer agent after an independent (Codex) review of PR #73; needs the owner to accept, amend or reject. It describes what the merged Android app (`apps/android`, `adb reverse`) and the iPhone app (`apps/ios`, `tools/ios/bridge.py`) already do; the transport is NOT changed by this entry.
**Decision:** A Tell phone app (the product is being renamed from Doublespeak to Tell) may send microphone audio to the user's OWN computer over a direct USB cable only: `adb reverse` on Android, usbmuxd / `iproxy` on iPhone (never `-n`, never a network device). Never over Wi-Fi, LAN, a relay or the cloud. On the computer the audio goes only to the loopback engine (D-009, D-011), is analysed in RAM and nothing is stored on the phone or the computer. The UI, docs and every claim say exactly this: "your own devices" / "only to your own computer over the USB cable", never "the audio never leaves the device".
**Why:** D-004 and D-009 say caller audio never leaves the device and reaches 127.0.0.1 only. A phone companion cannot run the models (Pellav2, Whisper, the LLM) on the phone, so the phone's audio has to reach the user's computer. A cable keeps it between two devices the same person owns and physically controls, with no network path; the wording has to match that instead of overstating it.
**Assumptions (unverified):** (1) usbmuxd and `adb reverse` carry the stream point to point over the cable and expose nothing on the LAN (iproxy listens on 127.0.0.1; the app's server listens on the phone's loopback only). (2) The person running the computer is the person holding the phone. (3) Speaker-mode audio also contains the user's own voice and the room; this entry covers that too.
**Consequences:** D-004/D-009 stay the rule for the analysis path on the computer; this entry is the one named exception for getting a companion phone's microphone audio there. Any change of transport (Wi-Fi, Bluetooth, a server) needs a new decision. `docs/android/ANDROID.md` and `docs/ios/IOS.md` cite D-012 and use the "your own devices" wording; the app copy already says "Audio goes only to your computer over USB. Nothing is saved."

## D-013 · 2026-11-07 · Name is Tell (supersedes D-010)
**Decision:** Owner decision: the product is called **Tell** everywhere a person or a developer sees a name. Supersedes D-010 ("Doublespeak") and restores D-001's name. Tagline stays "Every voice has a tell."
**Renamed:** every visible string (web page, site, Android PWA + Capacitor app name + notification, iOS `CFBundleDisplayName` and copy, macOS menu-bar app: `PRODUCT_NAME`/`CFBundleName`/`CFBundleDisplayName` Tell so it builds as `Tell.app`, menus, windows, notifications), tool banners and consent lines (`tools/macos/listen.py`, `tools/ios/bridge.py`), FastAPI title and fixed verdict wording, README/docs/skills/pm going forward. Python package `services/api/doublespeak` → `services/api/tell` (`git mv`); uvicorn target `tell.main:app` in the Makefile, CI, tools and the menu-bar app. Settings `DOUBLESPEAK_*` → `TELL_*`, read only through `tell/env.py`; keychain service `doublespeak` → `tell`; private CoreAudio tap names; `.cursor/rules/tell.mdc`; npm package name `tell-android`.
**Kept, on purpose:** (1) iOS/macOS/Android bundle and application ids `dev.doublespeak.*`, app group, keychain group, the iOS `dev.doublespeak.blocklist` keychain service and `com.doublespeak.tap-audio`: the apps are installed and signed on the owner's devices and TCC/keychain grants are tied to these ids. (2) The GitHub repo name `aaravjain151/doublespeak`. (3) Git history, and history entries in `pm/SESSION_LOG.md`, `pm/DECISIONS.md` (D-010 etc.) and dated reports such as `pm/FINDINGS-call-connection.md`. (4) Xcode project, target, folder and Swift module names (`Doublespeak`, `DoublespeakBar`): renaming them risks the builds for no user-visible gain. (5) Verdict signature prefix `ds1:`: it versions the signature format, not the brand; changing it would make every existing signature and the embedded demo samples fail verification, and a new prefix only earns its place with a real format change (then `tell2:` with a verifier that still accepts `ds1:`). (6) `ds-` localStorage keys in the web page (neutral, no migration needed). (7) The root-level legacy Streamlit prototype package `doublespeak/` (`app.py`, `finetune/`, root `tests/`): only its visible strings changed; it now also reads `TELL_DATA_DIR`/`TELL_MODELS_DIR`/`TELL_FINETUNED` with the old names as fallback; its own keychain item stays "doublespeak". (8) API URL paths.
**Compatibility:** `services/api/doublespeak/` is a deprecated one-file shim: `doublespeak.X` is the very same module object as `tell.X`, so `uvicorn doublespeak.main:app` and old imports keep working (DeprecationWarning). Old `.env` files keep working: `TELL_X` wins, else `DOUBLESPEAK_X`. Existing encrypted history, block list, feedback and personal-learning files stay readable: the key provider reads keychain service "tell", else copies the legacy "doublespeak" key (left in place), and only mints a key when neither exists. The menu-bar app falls back to `doublespeak.main:app` when pointed at a pre-rename checkout.
**Consequences:** delete the shim and the `DOUBLESPEAK_` fallback once nothing launches the old names (no date set). A `Doublespeak.app` built before this change is a separate bundle on disk; delete it and re-enable launch at login in `Tell.app` (docs/macos/MENUBAR.md).
