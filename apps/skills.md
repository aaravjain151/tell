# apps/ — skills.md (frontend domain; see also design/skills.md)

## Purpose
`apps/web/index.html` is the whole UI: one self-contained page, no build step, opens from `file://`, `make web`, or as a Claude Artifact.

## Layout
Default screen is the LIVE view (calm, no preset transcript): empty state, or when a call is on a listening bar + one verdict card + 2x2 + scores + call timeline + transcript. All demo tools (samples, generated attacker calls, source picker, Record/Upload/Speak, Simple/Detailed switch) sit in one collapsed `More` disclosure at the bottom (`?demo=1` opens it). Older description of the demo (Detailed) layout:
Two-column instrument panel: left = input (samples, transcript, audio file / mic, Analyze, Speak), right = verdict card → three gauges → tells grouped by family → privacy proof (bytes-out counter, signature, request log). Stacks at ≤ 780 px.

## Data contract (from `POST /analyze`)
`{tier, p_ai, p_scam, confidence, disclosed_ai, headline, advice, tells[{name, family, score, weight, evidence, applicable}], thresholds_version, egress{caller_audio_bytes_sent, bytes_sent_external, external_requests, context}, signature, cost{latency_ms}}`.
`render(v)` is the only function that touches the verdict DOM. Samples embedded in `#samples-data` are real engine output (regenerate with `./.venv/bin/python apps/web/build_samples.py` if thresholds change).

## Rules
- Vanilla JS, CSS vars only; colours and fonts come from `design/tokens.json` (copy the values, keep names aligned).
- Status is never colour-only: tier label + coloured rail + headline.
- Demo mode (no API) must still show a complete, honest verdict; never fake a live analysis.
- Mic → `MediaRecorder` webm → API needs ffmpeg; the status line says so.
- The artifact sandbox refuses the mic; that's expected. The real demo runs from `make web` + `make api` on the laptop.
- Never write "safe"/"illegal" in UI copy (design/skills.md voice rules).

## Validation
```
make web   # http://localhost:5173 — check at 380 px and 1200 px, light and dark
make api   # verdict card updates from the live engine; log shows "loopback only"
```
Regenerate samples after a thresholds change (see services/api/skills.md), re-inject into `#samples-data`.

## Recent lessons
- 2026-11-07 · frontend · Samples are injected at build time (`__SAMPLES__` placeholder) because an artifact can't fetch a sibling JSON unless it is published alongside; keep them inline.
- 2026-11-07 · frontend · A context line under the gauges shows duration, band-limited, transcript source and local scam-talk model from `egress.context`/`cost`; the bytes counter reads the server's `caller_audio_bytes_sent` (verified 0 with whisper + wav2vec2 + Ollama all on).
- 2026-11-07 · frontend · Doublespeak UI rebuild: paper (the call, caller's own words marked where a tell fired) beside a telescreen (verdict) with the privacy proof as its own card. Marks come from the quoted phrases in `tells[].evidence` matched against `verdict.transcript` (new additive field), so every evidence string that quotes a phrase becomes an underline; unquoted tells (pause rhythm etc.) stay in the list.
- 2026-11-07 · frontend · The page had no `<meta charset>` and `python -m http.server` sends no charset, so `·`, `—` and emoji rendered as mojibake; always declare utf-8 and use inline SVG icons, never emoji.
- 2026-11-07 · frontend · No web fonts or CDNs on purpose: the privacy demo must work with Wi-Fi off. System stacks only (Charter/Iowan for the transcript, system-ui for UI).
- 2026-11-07 · frontend · Testing recipe without a browser extension: headless Chrome `--screenshot` with `--virtual-time-budget`. Headless enforces a ~500 px minimum window, so check phone layout by screenshotting a wrapper page with a 390 px `<iframe>`. Virtual time freezes CSS transitions mid-flight (faded chips, empty bars): add `--force-prefers-reduced-motion` to see the final state, and confirm JS state with `--dump-dom`. `?theme=light|dark` forces a theme.
- 2026-11-07 · frontend · Red-team chip row (`#rt`) is built only after `probe()` succeeds and `/redteam/samples` returns >= 1 clip; any failure hides it. Chips reuse `.sample` so existing aria-pressed resets cover them; `attach()`/`clearAudio()` reset `rtCur`. A class that sets `display` beats the `hidden` attribute: `.rt-q{display:inline-flex}` kept the Opus toggle visible with no clip selected until `.rt-q[hidden]{display:none}` was added. Long chip lists collapse to 6 (4 at <= 480 px) behind "Show all N" instead of a clipped scroll box. :8000 is often taken by another worktree's API; to test a branch, copy index.html with the API const swapped to another port into the scratchpad (never edit the real one).
- 2026-11-07 · frontend · Editorial redesign (reference: mohnishgopi.com, brand from the team logo): white page, navy ink `#141D44`, teal `#189192` = the machine half, red `#F73C45` = flag; giant light uppercase verdict (Outfit 200), tiny nav with live clock, flat grey plane instead of cards. Everything glossy (glass panel, pills, glow, gradients, noise, scanlines, ghosted wordmark) was removed because it read as AI-generated. Smooth means human, stepped means machine: meters are 20 discrete cells, counters count in 16 steps, the hero rule draws with `steps(28)`.
- 2026-11-07 · frontend · Logo: `design/logo/` holds the original PNG, a traced vector (`doublespeak-mark.svg`, `doublespeak-icon.svg`) and the OFL licence of the embedded font. The vector is a faithful trace, not the designer's source; swap in the original vector if one exists. The nav inlines the glyph with `currentColor` for the navy half so it flips in dark mode.
- 2026-11-07 · frontend · Font is Outfit (OFL), subset to Latin and weights 200-600, 22 KB woff2, base64-embedded: still zero network. Regenerate with fonttools `instancer` + `subset` (see git history of this line).
- 2026-11-07 · frontend · `display:flex` on a class beats the `[hidden]` attribute; add a global `[hidden]{display:none!important}` (this showed an empty "Generated attacker calls" row).
- 2026-11-07 · frontend · Cursor review fixes worth keeping as rules: never repaint a different verdict after a failed request (restore headline/advice only, keep the user's transcript); show verdict time only for a live response; clear animation timers at the start of `render`; guard `getUserMedia` against double clicks, pick a supported MediaRecorder mime type (Safari is audio/mp4), reject empty/short recordings and always stop the tracks; touch devices need click-to-show tooltips because `pointerout` fires immediately; give `role="alert"` an always-in-tree element (`:empty` collapse, not `display:none`); no `role="status"` on a node that is rewritten every verdict.
- 2026-11-07 · frontend · Audio-source picker (how the app hears a REAL call): a device dropdown (virtual devices such as BlackHole/Loopback/Multi-Output are tagged "call audio"), a 4 s "Check level" meter that proves the source is not silent before anyone relies on it, the choice remembered in localStorage, and a clear error when a recording is silent. Recording captures RAW audio: `echoCancellation`, `noiseSuppression` and `autoGainControl` are all off, because browser DSP rewrites the pauses, room noise and loudness our detectors measure and noise suppression makes a human's background look like digital silence (verified in a real Chrome with a fake mic: the three settings read back false).
- 2026-11-07 · frontend · Stale-text bug: the page loads with a sample transcript pre-filled, and `analyze()` sends the text box together with any audio, so a new recording was judged by the OLD sample's words ("Scam pattern" for a beep). `dropSampleTranscript()` clears an unchanged sample transcript when recording or uploading starts. Rule: never let pre-filled text ride along with new audio.
- 2026-11-07 · frontend · Real-browser test recipe (no extension needed): launch Chrome headless with `--remote-debugging-port`, `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`, drive it over the DevTools protocol with Node's built-in WebSocket and read DOM state in REAL time. `--dump-dom` with `--virtual-time-budget` cannot wait on real audio hardware. The page accepts `?api=http://localhost:<port>` for a test API, restricted to loopback hosts so a crafted link can never aim the recorder at another machine.
- 2026-11-07 · frontend · Simple view (for the OLDER PROTECTED PERSON, idea from Samarth's mockup, built by Cursor in a sandboxed worktree and finished here): `?view=simple` or the nav switch; one headline, the advice at 24 px or more, at most 3 plain "Why we think so" bullets from a tell-to-sentence map, "Call someone you trust" with contacts stored ONLY in localStorage (never a made-up number; his mockup's 555 numbers were fake), big Record and Check buttons, "Words we heard (kept on this device only)", a provenance badge (Live analysis / Sample (stored) / Your transcript) and a permanent "Doublespeak can be wrong." Gotcha that cost an hour: the form's styles targeted `.trust-form` but the element had no such class, so the contact form rendered with raw browser defaults. When a screenshot shows unstyled controls, check the selector actually matches before touching the CSS.
- 2026-11-07 · frontend · Scores in the UI: Simple view has a 'How serious' block (Low/Medium/High word, three scores, 'scores, not probabilities'); Detailed view adds a one-line level and a 'Voice score over the call' strip (one pixel column per window, dashed line at P_AI_THRESHOLD read from /thresholds, hidden under 2 windows, aria-label with min/max/last). `scoresOf(v)` uses `v.scores` else recomputes from p_ai/p_scam/confidence so old stored samples work. The hero 'Doublespeak can be wrong.' is hidden in Simple once a verdict exists because the score block says it. Stored samples have no voice_windows (no neural model in the deterministic build), so the strip only appears with a live Pellav2/HF run; to eyeball it inject voice_windows into a scratch copy. Headless Chrome ignores `--blink-settings=preferredColorScheme=1` here: set `data-theme` on the root in a scratch copy for dark screenshots.
- 2026-11-07 · frontend · Voice x content grid under the headline (`#quad`, `renderQuad`, `quadrantOf` mirrors quadrant.py so stored samples work): Simple shows a 2x2 (rows human/AI voice, columns not scam/scam) with the active cell filled and a one-sentence label, role=img with an aria-label; Detailed shows only the sentence. Unclear axes draw dashed outlines on the candidate cells instead of a fill. Muted cells need a visible border (`--unsure`); `--line` vanishes in dark. Headless Chrome min window width is about 500, so test 390 by putting the page in a 390px iframe; also disable the headline `rise` animation and transitions in the harness or screenshots catch the previous state.
- 2026-11-07 · frontend · Live view (`feat/live-ui`): `html[data-live]` = empty | offline | on | demo decides which blocks show (CSS only); `render()` and `setBusy(true)` switch to `demo`, SSE events switch to `on` (a live call takes over). The page consumes `GET /live/events` (EventSource, backoff 1..15 s) with events state / verdict / ended and `POST /live/dismiss`; it ASSUMES `POST /live/stop` (the contract has none; a failure shows 'Could not stop from here'). Card follows `stable.tier`; if a tick disagrees with it, the 2x2 and scores are recomputed from the stable tier so the card never contradicts itself. Headline cross-fades (no rise animation), 'Changed to X at m:ss' appears on a stable-tier change, red banner only for `stable.alert==='red'` (Dismiss hides it locally until alert leaves red), amber shows one caution line. 'Start listening now' reuses the existing Record path (30 s recording then /analyze); there is NO browser ws /ws/stream code on main yet, so it is not a continuous live listener.
- 2026-11-07 · frontend · Test without the engine: `python3 apps/web/mock_live.py [--script scam|ai|both --interval 2 --clock 3 --stop-at N --hold-ended --idle]` then `index.html?api=http://127.0.0.1:8123`.
