# apps/ — skills.md (frontend domain; see also design/skills.md)

## Purpose
`apps/web/index.html` is the whole UI: one self-contained page, no build step, opens from `file://`, `make web`, or as a Claude Artifact.

## Layout
Default screen is the LIVE view (calm, no preset transcript): empty state, or when a call is on a listening bar + one verdict card + 2x2 + scores + call timeline + transcript. All demo tools (samples, generated attacker calls, source picker, Record/Upload/Speak, Simple/Detailed switch) sit in one collapsed `More` disclosure at the bottom (`?demo=1` opens it). Older description of the demo (Detailed) layout:
Two-column instrument panel: left = input (samples, transcript, audio file / mic, Analyze, Speak), right = verdict card → three gauges → tells grouped by family → privacy proof (bytes-out counter, signature, request log). Stacks at ≤ 780 px.

## Data contract (from `POST /analyze`)
`{tier, p_ai, p_scam, confidence, disclosed_ai, headline, advice, tells[{name, family, score, weight, evidence, applicable}], thresholds_version, egress{caller_audio_bytes_sent, bytes_sent_external, external_requests, context}, signature, cost{latency_ms}}`.
`render(v)` is the only function that touches the verdict DOM. Samples embedded in `#samples-data` are real engine output (regenerate with `./.venv/bin/python apps/web/build_samples.py` if thresholds change).

## Rules
- Vanilla JS, CSS vars only; colours and fonts come from `design/tokens.json` (copy the values, keep names aligned).
- Status is never colour-only: tier label + coloured rail + headline.
- Demo mode (no API) must still show a complete, honest verdict; never fake a live analysis.
- Mic → `MediaRecorder` webm → API needs ffmpeg; the status line says so.
- The artifact sandbox refuses the mic; that's expected. The real demo runs from `make web` + `make api` on the laptop.
- Never write "safe"/"illegal" in UI copy (design/skills.md voice rules).

## Validation
```
make web   # http://localhost:5173 — check at 380 px and 1200 px, light and dark
make api   # verdict card updates from the live engine; log shows "loopback only"
```
Regenerate samples after a thresholds change (see services/api/skills.md), re-inject into `#samples-data`.

- 2026-11-07 · frontend · Companion-client rules from the Codex review of the iOS bridge: (1) never relay `GET /live/events` or call `POST /live/dismiss` from a per-device client: both are global (no session ids), so another listener's transcript reached the phone and a phone Dismiss cleared the Mac alert. Use the client's OWN `/ws/stream` session: its `verdict` messages now carry the full verdict (additive `verdict` field, mix cap applied to the nested scores) and its `{"type":"dismiss"}` is scoped. (2) Forward a server `final`/`error`/closed socket to the device as `ended` and stop capture there; never return silently. (3) Re-check every request is loopback and refuse redirects (same `_NoRedirect` as `tell/localhost.py`), not only the URL at startup. (4) Audio start must roll back tap, framer and session on any failure (`CaptureBackend` seam + fake in XCTest). (5) Wording: "only to your own computer over the USB cable", never "never leaves the device" (PROPOSED D-012).

- 2026-11-08 · frontend · Android auto-listen (feat/android-autostart, docs/android/ANDROID.md "Auto-listen"): (1) the page's WebView capture cannot be started from a call, so auto-listen captures NATIVELY in its own microphone service (`CallListenService`, AudioRecord 16 kHz) and streams with plain Java sockets (`call/LoopbackEngine`, 127.0.0.1 hard-coded, `Origin: http://localhost` because POST /session requires an allowed Origin; no OkHttp because nothing was cached and minSdk 22 also rules out java.util.Base64). (2) Android 11+ will not let a background app start a microphone service (11: silence, 12-13: ForegroundServiceStartNotAllowedException, 14: SecurityException), and PHONE_STATE is not an exemption: the only compliant background path is a high-priority notification whose Listen action is `PendingIntent.getForegroundService`. Decide with a pure `StartPolicy(sdk, appResumed)` and track "resumed" (not "started") activities. (3) Speakerphone cannot be switched by an ordinary app during a cellular call on 12+; open the in-call screen with `TelecomManager.showInCallScreen` instead. (4) AOSP silences ordinary apps' microphones while a call is active: build the 8 s silence notice in, and make it the first item of the real-call test. (5) Keep the logic in pure Java (`call/`) so `./gradlew testDebugUnitTest` covers the state machine, policy, permission gate and session outcomes with fakes; add an opt-in test against the real engine (`TELL_ENGINE_PORT`). (6) Lint caught `toLowerCase()` without a Locale on enum names ("IDLE" breaks on a Turkish phone). (7) Worktree-isolated agents: heredocs and `$VAR` command names in Bash get refused; write scripts to the scratchpad and run them with `bash file`.
